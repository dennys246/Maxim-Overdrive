## New findings

| Id | Severity | file::symbol | Finding and failure scenario |

| ED1 | SHOULD-FIX | `1a_records_design.md`::Exit test (the status grep) | The regex `^\|[^\|]*(^\|[ ,*\|])$id([ ,*]\|\|).*\| *\**(fixed\|deferred\|rejected)` puts a greedy `.*` before the status cell. It therefore accepts **any** later cell that begins with `fixed`, `deferred` or `rejected`, including the reason column. I ran it on a sample in a `mktemp` dir: the row `\| C2 \| open \| fixed later maybe \|` passes, which is wrong. `A-B2` bold `deferred`, `C1, W1` and `W4 \| rejected (author)` pass; `C3 \| partly fixed`, `W2 \| open` and an id that appears only inside another row fail, which is right. Failure: a delta reviewer marks a BLOCKER `open` with a reason such as "fixed in §5 but §9 still…", and the exit test reports the BLOCKER as resolved. The brief also never tells the session to name the delta reports `delta*.md`: only the exit test's `ls` implies it, so reports named `round2_*.md` make `ls` fail. Proposed fix (unverified): anchor the status to the second cell, for example `^\|[^\|]*<id>[^\|]*\| *\**(fixed\|deferred\|rejected)`, and state the file names in Order step 5. |
| ED2 | SHOULD-FIX | `2_drift_and_lock.md`::"Trigger for the repeat"; `3_upstream_sync.md`::"After this step"; O79 part 3 | Two briefs are rerun as fresh sessions: brief 2's repeat at 1.3.5, and the lane at each Overdrive tag and each Maxim release. Both briefs hard-code the first run's ids ("only the ids O79 reserves for you: lesson number 41 and B49 to B51"; step 3 has lesson number 42 and B52 to B54), and their file lists restrict lessons and backlog to those ids. By the time a rerun starts, the first run has used them. O79 reserves ids only for "the three steps that run together", and it forbids reruns only while step 4 is open. A rerun can therefore overlap step 5, or another rerun, and neither has a reservation. Failure: the 1.3.5 repeat obeys its brief, writes lesson number 41 again, and `lint_ids` fails locally. Or it takes the next free id on its own, while step 5 takes the same one on its branch, and E11's duplicate-id merge comes back. Proposed fix (unverified): say that the ids apply to the first run only, and give reruns a rule, such as a reservation from the planning session or no record ids outside their review record. |
