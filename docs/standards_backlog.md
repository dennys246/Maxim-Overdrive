# Standards backlog: rules waiting for a check

Every rule in CLAUDE.md's "Engineering standards" names its guard. A rule that nothing checks yet points here, so
the gap stays visible. Mechanizing a row beats adding a rule. When a row's check lands, cite the check in CLAUDE.md
and mark the row **done** with the commit, rather than deleting it.

| ID | Rule it enforces | The check | Lands with |
|---|---|---|---|
| B1 | Pre-push review | The hand-off note and PR description carry a round summary (lenses, severity counts, deferrals), and no `src/` commit after the last round goes unreviewed. Process today; a check could compare the reviewed commit with the pushed head. | open |
| B2 | Determinism and replay | The server records every accepted intent with its turn. A replay test feeds a recorded log back in and gets bit-identical state. The replay's inputs are the log, the scene, the rig and the world config, which now includes `data/world/actions.yaml` (the action limits), so the log header must record them. | Phase 1 step 2 |
| B3 | Versioned formats | Golden wire fixtures under `tests/fixtures/wire/`, decoded by the Python tests and by the GDScript client tests, so both sides prove they read the same bytes. Unknown protocol versions are refused at the handshake. Imagined specs have no version of their own: the protocol message or intent-log record that carries one is versioned, so a change to the keys a spec may carry (`imagination.spec.SPEC_KEYS`) is a protocol and intent-log version bump, with an old replay refused for its version rather than misread. | Phase 1 steps 2 and 4 |
| B4 | Versioned formats | Save format v0: a round-trip test plus a committed golden save that every later version must still load or refuse loudly. | Phase 1 (save v0) |
| B5 | Performance budgets | A benchmark per profile on the first tile: turn time, snapshot encode time and bytes. A regression of more than 20% against the committed baseline fails pre-push. The budgets are set from the first measurements, not guessed. | Phase 1 step 3 |

| B7 | Client standards; exit tests | Golden screenshots: a scripted scene at a fixed camera and turn, rendered at each profile and compared with a perceptual tolerance. This is how "looks the same apart from detail" becomes a test. | Phase 1 step 5 |

| B12 | Assets and data | Every file under `data/` loads and validates in a test (materials, rigs, scenes, world config), so a malformed data file fails pre-push rather than at launch. Partly in place: `data/world/actions.yaml` loads strictly with every rejection path tested, every number in every loader goes through `checks.finite_real` or `checks.whole_number`, and `tests/test_act_validation.py::test_no_data_file_writes_a_number_as_a_string` catches YAML 1.1's `1.0e7`-is-a-string trap. Still open: physical ranges for the rig and material loaders (today they accept a negative density or conductivity). Format versions for these files are B21. | Phase 1 step 3 |
| B13 | No silent swallows | Ruff's BLE and S110 catch `except Exception` and `except: pass`. They don't catch a narrow `except` that returns a fallback without reporting it; that is a reviewer's job until a lint exists. | open |
| B14 | The client is untrusted input | Server tests that refuse: a handshake with any `Origin` header, a missing or wrong token, an unknown protocol version, malformed and oversized messages (an error reply, state unchanged). | B19 | Separation of concerns | The size tripwires catch a god function's size, not its mixed concerns. Missing: (1) **layer contracts**, import-linter in `scripts/prepush.sh` with the engine layers as a `layers` contract and a `protected` contract around the sealed core, so a package can't import upward or reach past the Maxim membrane. (4) `scripts/lint_standards.py` holds five checks in one module; split it into one module per check before the next check lands. | (1) Phase 1, the boundaries step, once `docs/design/boundaries.md` merges; (2), (3) open; (4) before the next check |
| B20 | Assume other agents are working | Checked: the gate refuses `main` and the main checkout (GitHub Actions exempt, and its PASS line says so); a scan keeps Python's paths, environment reads and test ports private to a session and routes tests' git calls through `tests/_gitutil.py`; the gate never offers an install into a venv outside the worktree. Held by review: no bare `git stash`/`stash pop`; no pruning, deleting, resetting or force-moving another session's branch or worktree; looking before deleting; no `pip install` into a shared venv; no `git config` write without `--worktree` (config and hooks are shared by every worktree); no long-running server left behind. Not covered: editing or committing in the main checkout is caught only at the gate (a pre-commit hook, which every worktree shares, would catch it at commit time); a detached HEAD on main's commit passes; non-Python files (a `.sh` writing to `/tmp`) and computed paths aren't scanned; pytest's `tmp_path` lives under a shared basetemp, safe by pytest's own locking (`--basetemp` inside the worktree would make it private). A session claim file per worktree could follow. Once real Maxim agents run in tests, the scan must cover Maxim's shared paths too (`~/.maxim`, working-directory `data/`), which `npcs_and_sem.md` O13 keeps in each worker's agent home. | open |
